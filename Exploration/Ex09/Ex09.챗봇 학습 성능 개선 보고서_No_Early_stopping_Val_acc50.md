# Ex09 챗봇 학습 성능 개선 보고서

## 1. 보고서 목적

본 보고서는 `Ex09_val_acc50_no_early_stopping.ipynb`에 반영된 최신 학습 개선 내용을 설명합니다. 이번 수정의 핵심 목표는 검증 토큰 정확도인 **`val_acc`를 0.50 이상으로 높이는 것**입니다. 동시에 검증 지표가 일시적으로 정체되거나 상승하더라도 너무 이른 Early Stopping이 발생하지 않도록 조기 종료 기능을 기본적으로 비활성화했습니다.

`val_acc=0.50`은 검증 데이터에서 PAD 토큰을 제외한 실제 정답 토큰 중 약 50%를 모델이 정확히 예측한다는 의미입니다. 이 수치는 문장 전체가 정답과 일치한다는 뜻이 아니며, 생성 응답의 자연스러움이나 질문 의도 적합성을 완전히 나타내는 지표도 아닙니다.

## 2. 기존 문제 분석

기존 학습 로그에서는 훈련 손실이 계속 감소했지만 검증 손실은 약 12 epoch 이후 상승했습니다. 이는 모델이 훈련 데이터의 토큰 패턴을 과도하게 학습하는 과적합 신호입니다. 또한 검증 손실 기준 Early Stopping이 너무 일찍 동작하면, `val_acc`가 뒤늦게 상승할 가능성을 확인하지 못한 채 학습이 종료될 수 있습니다.

| 문제 | 영향 |
|---|---|
| 훈련 손실만 지속적으로 감소 | 훈련 데이터 암기 가능성 증가 |
| 검증 손실의 조기 상승 | 일반화 성능 저하 가능성 |
| 검증 손실만 기준으로 best 모델 선택 | `val_acc`가 높은 모델이 선택되지 않을 가능성 |
| 짧은 patience | 정확도가 상승하기 전에 학습 종료 가능 |
| label smoothing 사용 | 손실 안정화에는 도움이 될 수 있으나 token accuracy 목표에는 불리할 수 있음 |

## 3. 최신 수정 내용

이번 수정본은 검증 손실보다 **검증 정확도 `val_acc`를 우선 기준**으로 모델을 선택하도록 변경했습니다. 각 epoch에서 검증 정확도가 이전 최고값보다 높아지면 해당 가중치를 best 모델로 저장합니다. 검증 정확도가 같거나 거의 같은 경우에는 검증 손실이 낮은 모델을 우선합니다.

| 항목 | 기존 설정 | 최신 설정 | 기대 효과 |
|---|---:|---:|---|
| 목표 검증 정확도 | 별도 목표 없음 | `TARGET_VAL_ACC=0.50` | 목표 지표를 명확하게 관리 |
| Early Stopping | 검증 손실 정체 시 동작 | 기본 비활성화 | 정확도 상승 전 조기 종료 방지 |
| 학습 epoch | 30 | 60 | 정확도 상승을 위한 학습 기회 확대 |
| 학습률 | `5e-4` | `3e-4` | 큰 업데이트로 인한 불안정성 완화 |
| Dropout | `0.15` | `0.10` | 과도한 정규화 완화 및 학습 표현력 확보 |
| Label smoothing | `0.05` | `0.0` | token accuracy 최적화에 집중 |
| CPU batch size | 32 | 16 | 메모리 부담을 낮추고 업데이트 빈도 증가 |
| Best 모델 기준 | 검증 손실 중심 | `val_acc` 우선, `val_loss` 보조 | 목표 지표에 맞는 모델 선택 |
| 체크포인트 | 검증 손실 최저 모델 | 검증 정확도 최고 모델 | 실제 목표에 맞는 추론 모델 사용 |

## 4. 핵심 하이퍼파라미터

최신 노트북에는 다음 설정이 반영되어 있습니다.

```python
TARGET_VAL_ACC = 0.50
ENABLE_EARLY_STOPPING = False
PATIENCE = 20
MIN_DELTA = 1e-4

LEARNING_RATE = 3e-4
WEIGHT_DECAY = 1e-5
LABEL_SMOOTHING = 0.0
EPOCHS = 60
DROPOUT = 0.10
BATCH_SIZE = 4 if device.type == 'cuda' else 16
```

`ENABLE_EARLY_STOPPING=False`이므로 기본 실행에서는 `stale_epochs`가 `PATIENCE`에 도달해도 학습이 종료되지 않습니다. 따라서 모델은 목표 `val_acc`에 도달했는지 여부와 관계없이 최대 `EPOCHS`까지 학습합니다. 다만 매 epoch에서 최고 `val_acc` 모델은 계속 저장되므로, 마지막 epoch 모델이 과적합되더라도 학습 종료 후 best 모델이 복원됩니다.

## 5. 수정된 학습 로직

학습 함수는 다음과 같이 `val_acc`를 기준으로 best 모델을 선택합니다.

```python
improved = (
    valid_acc > best_val_acc + min_delta
    or (
        abs(valid_acc - best_val_acc) <= min_delta
        and valid_loss < best_val_loss
    )
)
```

검증 정확도가 의미 있게 상승하면 다음 값이 갱신됩니다.

```python
best_val_acc = valid_acc
best_val_loss = valid_loss
best_epoch = epoch + 1
```

또한 실행 로그에 목표 도달 여부가 표시됩니다.

```python
target_msg = 'TARGET REACHED' if valid_acc >= target_val_acc else ''
```

예상 로그는 다음과 같은 형태입니다.

```text
Epoch 20/60 | train loss 2.10 acc 0.57 | val loss 3.90 acc 0.48 | lr 3.00e-04 | stale 2/20
Epoch 25/60 | train loss 1.80 acc 0.61 | val loss 3.92 acc 0.50 | lr 3.00e-04 | stale 1/20 TARGET REACHED
Best model restored from epoch 25 | best val_acc: 0.5032 | best val_loss: 3.9200
Best val_acc: 0.5032
```

실제 epoch와 수치는 실행 환경에 따라 달라질 수 있습니다. `TARGET REACHED`가 표시되면 해당 epoch에서 검증 정확도 50% 목표를 달성한 것입니다.

## 6. 실행 방법

노트북은 반드시 첫 셀부터 순서대로 실행해야 합니다. 특히 모델 생성 셀 이후의 학습 준비 셀에서 `criterion`, `optimizer`, `scheduler`, `CHECKPOINT`가 생성된 뒤 `%%time` 학습 셀을 실행해야 합니다.

```python
%%time
history = train(
    model=model,
    dataloader=dataloader,
    optimizer=optimizer,
    loss_function=loss_function,
    scheduler=scheduler,
    num_epochs=EPOCHS,
    device=device,
    valid_dataloader=valid_loader,
    patience=PATIENCE,
    min_delta=MIN_DELTA,
    accumulation_steps=ACCUMULATION_STEPS,
    checkpoint_path=CHECKPOINT,
    enable_early_stopping=ENABLE_EARLY_STOPPING,
    target_val_acc=TARGET_VAL_ACC,
)
print('Best val_acc:', history['best_val_acc'])
```

학습 완료 후에는 다음 값들을 확인합니다.

| 확인 값 | 의미 |
|---|---|
| `history['best_val_acc']` | 전체 학습 중 가장 높았던 검증 정확도 |
| `history['best_val_loss']` | best `val_acc` 모델의 검증 손실 |
| `history['best_epoch']` | best 모델이 만들어진 epoch |
| `history['valid_acc']` | epoch별 검증 정확도 변화 |
| `history['train_acc']` | epoch별 훈련 정확도 변화 |

## 7. 과적합을 완전히 무시하지 않는 이유

이번 수정에서는 Early Stopping을 비활성화했지만, 과적합 자체가 사라지는 것은 아닙니다. 학습을 너무 오래 진행하면 훈련 정확도는 계속 상승하는 반면 검증 정확도는 정체되거나 하락할 수 있습니다. 따라서 학습 종료 후에는 마지막 모델이 아니라 `best_val_acc` 모델을 복원하여 사용합니다.

즉, 이번 구조는 다음과 같은 절충안입니다.

> **학습은 충분히 오래 진행하되, 추론에는 검증 정확도가 가장 높았던 모델만 사용한다.**

원한다면 이후 다음과 같이 Early Stopping을 다시 켤 수 있습니다.

```python
ENABLE_EARLY_STOPPING = True
PATIENCE = 20
```

이 경우에는 `val_acc`가 `MIN_DELTA` 이상 개선되지 않는 상태가 20 epoch 연속 유지될 때 학습이 종료됩니다. `PATIENCE`를 5처럼 작게 설정하면 목표 정확도에 도달하기 전에 종료될 수 있으므로, 현재 목표에서는 15~20 정도의 비교적 큰 값을 권장합니다.

## 8. 50% 목표의 해석과 한계

`val_acc=0.50` 달성은 코드 구조상 목표로 설정할 수 있지만, 특정 수치를 반드시 보장할 수는 없습니다. 실제 성능은 데이터 분할, SentencePiece vocabulary, PyTorch 버전, 초기 가중치, CPU/GPU 환경, 학습 시간, 데이터의 질문–답변 난이도에 영향을 받습니다.

또한 token accuracy가 50%라고 해서 챗봇의 모든 응답이 자연스럽거나 정답 문장과 동일하다는 뜻은 아닙니다. 최종 평가에서는 다음 지표를 함께 확인해야 합니다.

| 평가 관점 | 확인 방법 |
|---|---|
| 토큰 예측 정확도 | `best_val_acc` 확인 |
| 일반화 손실 | `best_val_loss` 확인 |
| 응답 반복 | 동일 문구 반복 여부 확인 |
| 빈 응답 | 생성 결과가 빈 문자열인지 확인 |
| 질문 적합성 | 대표 질문에 대한 정성 평가 |
| 테스트 성능 | 학습·튜닝에 사용하지 않은 테스트 셋 평가 |

## 9. 최종 파일

최신 수정 노트북은 **`Ex09_val_acc50_no_early_stopping.ipynb`**입니다. 이 노트북에는 `val_acc=0.50` 목표, Early Stopping 기본 비활성화, `val_acc` 기준 best checkpoint 저장, 최고 모델 복원, `%%time` 학습 실행 코드가 포함되어 있습니다.

현재 실행 환경에서 PyTorch 학습을 직접 재실행하지 않았으므로, 본 보고서에는 실제 달성 수치를 임의로 기재하지 않았습니다. 노트북 실행 후 마지막 로그의 `Best val_acc` 값을 이 보고서의 실제 결과란에 기록하면 됩니다.

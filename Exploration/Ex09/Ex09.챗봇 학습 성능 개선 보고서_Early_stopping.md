# Ex09 챗봇 학습 성능 개선 보고서

## 1. 보고서 개요

본 보고서는 `Ex09_train_function_early_stopping.ipynb`에 반영된 학습 성능 개선 내용을 정리한 문서입니다. 기존 노트북의 학습 코드를 `train()` 함수 중심으로 재구성하고, 검증 데이터 기반의 **Early Stopping(조기 종료)** 및 **Best Model 복원**을 추가했습니다. 따라서 이 보고서는 이전 `Ex09_improved.ipynb` 기준 보고서를 대체합니다.

## 2. 기존 학습 결과의 문제점

기존 로그에서는 훈련 손실이 계속 감소했지만 검증 손실은 약 12 epoch 전후에서 최저점에 도달한 뒤 상승했습니다.

| 구간 | 관찰된 결과 |
|---|---|
| Epoch 1~12 | 훈련 손실과 검증 손실이 함께 감소 |
| Epoch 12 전후 | 검증 손실 최저점 형성: 약 `3.8848` |
| Epoch 13~20 | 훈련 손실은 계속 감소하지만 검증 손실은 상승 |
| 마지막 epoch | 학습 데이터에는 더 잘 맞지만 일반화 성능은 악화 |

이 패턴은 **과적합**을 의미합니다. 기존 코드는 마지막 epoch의 모델을 저장해 추론에 사용했기 때문에, 검증 성능이 가장 좋았던 시점보다 성능이 떨어진 가중치가 사용될 수 있었습니다.

## 3. 이번 수정의 핵심

이번 수정에서는 학습과 검증을 하나의 `train()` 함수 안에서 처리하도록 구성했습니다. 학습용 `dataloader`로 파라미터를 업데이트한 뒤 매 epoch마다 `valid_dataloader`의 검증 손실과 정확도를 계산합니다. 검증 손실이 가장 낮아지면 해당 모델을 best checkpoint로 저장하고, 일정 epoch 동안 의미 있는 개선이 없으면 학습을 중단합니다.

> 검증 손실이 더 이상 개선되지 않을 때 학습을 계속하지 않고, 가장 성능이 좋았던 모델을 복원하여 추론에 사용하는 구조입니다.

## 4. 주요 변경 사항

| 구분 | 기존 상태 | 최신 수정 상태 | 기대 효과 |
|---|---|---|---|
| 학습 구조 | 학습 로직이 셀에 직접 작성됨 | `train()` 함수로 통합 | 재사용성과 실험 편의성 향상 |
| 실행 방식 | 학습 셀을 직접 실행 | `%%time`으로 `train(...)` 호출 | 전체 학습 시간 측정 가능 |
| 검증 | 학습 루프와 별도 관리 | `valid_dataloader`를 매 epoch 실행 | 일반화 성능을 직접 모니터링 |
| 과적합 제어 | 정해진 epoch까지 무조건 학습 | `PATIENCE=5` Early Stopping | 검증 성능 악화 구간의 학습 방지 |
| 개선 판정 | 별도 기준 없음 | `valid_loss < best_valid_loss - MIN_DELTA` | 미세한 변동을 개선으로 오판하지 않음 |
| 최소 개선 폭 | 없음 | `MIN_DELTA=1e-3` | 의미 있는 검증 손실 감소만 인정 |
| Best 모델 | 마지막 모델 저장 | 검증 손실 최저 모델 저장·복원 | 가장 좋은 일반화 모델 사용 |
| 체크포인트 | epoch별 마지막 상태 중심 | 개선된 epoch의 상태 저장 | 학습 중단 후에도 best 모델 보존 |
| 학습률 | 고정 또는 학습 손실 기준 | 검증 손실 기준 `ReduceLROnPlateau` | 검증 정체 후 안정적 미세 조정 |
| 손실 함수 | PAD 무시 | PAD 무시 + `label_smoothing=0.05` | 패딩 오차 제거 및 과도한 확신 완화 |
| metric 집계 | 배치 평균을 다시 평균 | 실제 non-PAD 토큰 수 기준 집계 | 배치별 패딩 수 차이에 따른 왜곡 감소 |
| 모델 표현력 | `FF_DIM=256` | `FF_DIM=512` | 서브워드 조합 표현력 보강 |
| 입력 길이 | `MAX_LENGTH=40` | `MAX_LENGTH=48` | 긴 질문·답변의 잘림 감소 |
| 추론 | 반복 제한 없음 | 반복 2-gram 억제 | 동일 구절 반복 출력 감소 |

## 5. Early Stopping 동작 방식

현재 하이퍼파라미터는 다음과 같이 설정되어 있습니다.

```python
PATIENCE = 5
MIN_DELTA = 1e-3
```

매 epoch마다 검증 손실을 확인하여 다음 조건으로 개선 여부를 판정합니다.

```python
improved = valid_loss < best_valid_loss - min_delta
```

검증 손실이 `best_valid_loss - MIN_DELTA`보다 작아지면 의미 있는 개선으로 간주하고 `stale_epochs`를 0으로 초기화합니다. 개선되지 않으면 `stale_epochs`를 1씩 증가시키며, 다음 조건을 만족하면 학습을 종료합니다.

```python
if stale_epochs >= patience:
    break
```

예를 들어 `PATIENCE=5`이면 검증 손실이 5 epoch 연속으로 의미 있게 좋아지지 않을 때 학습을 중단합니다. 학습 종료 시점의 모델이 아니라, 지금까지 검증 손실이 가장 낮았던 모델을 다시 로드합니다.

## 6. 실제 실행 코드

수정된 노트북의 학습 실행 셀은 다음과 같습니다.

```python
%%time
history = train(
    model=model,
    dataloader=dataloader,
    optimizer=optimizer,
    loss_function=loss_function,
    scheduler=scheduler,
    num_epochs=EPOCHS,
    device=device,
    valid_dataloader=valid_loader,
    patience=PATIENCE,
    min_delta=MIN_DELTA,
    accumulation_steps=ACCUMULATION_STEPS,
    checkpoint_path=CHECKPOINT,
)
```

여기서 기존 학습용 `train_loader`는 다음과 같이 `dataloader`로 연결되어 있고, 검증용 `valid_loader`가 Early Stopping에 사용됩니다.

```python
dataloader = train_loader
loss_function = criterion
```

학습 함수는 다음 정보를 `history`에 저장합니다.

| 키 | 내용 |
|---|---|
| `train_loss` | epoch별 학습 손실 |
| `valid_loss` | epoch별 검증 손실 |
| `train_acc` | PAD를 제외한 학습 토큰 정확도 |
| `valid_acc` | PAD를 제외한 검증 토큰 정확도 |
| `lr` | epoch별 현재 학습률 |
| `best_epoch` | 검증 손실이 가장 낮았던 epoch |
| `best_valid_loss` | 최저 검증 손실 |

## 7. 예상 출력과 해석

실행하면 다음과 유사한 로그가 출력됩니다.

```text
Epoch 1/30 | train loss 5.70 acc 0.25 | valid loss 5.26 acc 0.27 | lr 5.00e-04 | stale 0/5
Epoch 2/30 | train loss 4.99 acc 0.28 | valid loss 4.91 acc 0.29 | lr 5.00e-04 | stale 0/5
...
Early stopping at epoch 17. Best epoch: 12, best valid loss: 3.8848
Best model restored from epoch 12.
```

`stale 3/5`는 최근 3개 epoch 동안 검증 손실이 의미 있게 개선되지 않았다는 뜻입니다. `stale 5/5`가 되면 학습이 중단됩니다. 단, 실제 종료 epoch와 best epoch는 실행 환경과 난수 상태에 따라 달라질 수 있습니다.

## 9. 추가 권장 사항

Early Stopping은 과적합을 줄이고 가장 좋은 checkpoint를 선택하지만, 데이터 자체의 품질이나 모델의 의미 이해 능력을 근본적으로 해결하지는 않습니다. 이 데이터셋은 단일 질문–답변 쌍 중심의 약 1만 건 규모이므로, 더욱 자연스러운 대화를 생성하려면 다중 턴 문맥 데이터 또는 한국어 사전학습 모델의 fine-tuning을 고려할 수 있습니다.

또한 token accuracy만으로 응답 품질을 판단하기보다는 고정된 테스트 질문에 대해 질문 의도 적합성, 빈 응답 비율, 반복 응답 비율, 응답 길이, 정성 평가를 함께 기록하는 것이 바람직합니다.
